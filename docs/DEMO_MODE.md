# Demo mode

Демо-режим предназначен для независимой проверки продукта без доступа к рабочему
кабинету преподавателя и данным реальных учеников.

## Границы

- отдельные tenant ID преподавателя и ученика;
- заметная маркировка `Демо-режим` в teacher и student shell;
- реальные AI и голосовой ввод разрешены, но имеют отдельные дневные лимиты;
- создание Auth-аккаунтов, сброс паролей и загрузка/удаление файлов запрещены
  одновременно в UI и защищённом backend;
- изменения обычных данных разрешены только внутри demo tenant;
- рабочий tenant преподавателя недоступен по Firestore Security Rules.

Лимиты по умолчанию:

- AI: 12 запросов в день;
- голос: 3 записи в день.

Они задаются backend-переменными `DEMO_AI_DAILY_REQUEST_LIMIT` и
`DEMO_VOICE_DAILY_REQUEST_LIMIT`.

## Локальный dry-run и Emulator

Подготовить офлайн-план, не подключаясь к production:

```powershell
npm.cmd run demo:plan
```

Создать тестовые Auth users и 14 детерминированных документов можно только внутри
запущенных Firebase Auth и Firestore Emulator:

```powershell
npm.cmd run demo:seed:emulator
```

Повторный запуск идемпотентен. Сгенерированный план сохраняется в игнорируемой Git
папке `private/`.

Production apply, deploy backend/frontend и публикация логинов не входят в эти
команды. Они требуют отдельного подтверждения, предварительного read-only
inspection проекта `kabinet-25` и скрытого локального ввода новых паролей.
