# PROJECT SPEC v1
## Кабинет ученика

Дата: 14.08.2026

## 1. Цель

Единое рабочее пространство репетитора и ученика, которое:
- сокращает ручную рутину преподавателя;
- показывает ученику ДЗ, ближайший урок, материалы и прогресс;
- автоматически превращает результаты работ и пробников в аналитику;
- поддерживает расписание, переносы, оплату;
- мотивирует через XP, уровни, серии и достижения;
- расширяется без потери старых данных.

Главный UX-принцип: **одно действие преподавателя должно давать несколько полезных результатов.**

## 2. Роли

### Teacher
Может управлять учениками, программами, расписанием, ДЗ, результатами, пробниками, материалами, оплатой, XP и достижениями.

### Student
Входит по логину/паролю преподавателя, видит только свои данные, отправляет разрешённые результаты ДЗ и меняет только пользовательские настройки.

Ученик не меняет оценки, пробники, цель, оплату, XP и чужие данные.

## 3. Программы

Архитектура:
- `oge`
- `ege`
- `school`

Первая программа: **ОГЭ · Русский язык · 2027**.

В админке фильтр: **Все | ОГЭ | ЕГЭ | Школьная программа**.

## 4. Навигация преподавателя

Главная / Расписание / Ученики / Домашки / Материалы / Аналитика / Пробники

Внутри ученика:
Обзор / ДЗ / Пробники / Уроки / Оплата / Заметки

## 5. Главная преподавателя

Desktop-first.

KPI:
- Сегодня уроков
- Просрочено/не выполнено ДЗ
- Работ на проверку
- Требуют внимания

Сегодняшнее расписание показывает:
- локальное время учителя;
- МСК;
- ученика;
- тему;
- статус ДЗ;
- оплату;
- «На что обратить внимание»;
- кнопку открытия занятия.

## 6. Ученик

Mobile-first.

Нижнее меню:
Главная / ДЗ / Прогресс / Материалы / Профиль

На Главной:
- ближайшее занятие + «Подключиться»;
- главная цель;
- дней до экзамена;
- актуальное ДЗ;
- готовность;
- последний пробник;
- оценка;
- XP / уровень / серия;
- последнее достижение.

## 7. Расписание

Повторяющаяся серия хранится отдельно от конкретных уроков.

Без backend scheduler:
- teacher app материализует занятия до +12 недель;
- делает batch;
- не создаёт дубликаты.

Перенос:
- старый lesson → `rescheduled`;
- хранит `rescheduledToLessonId`;
- новый lesson → `planned`;
- хранит `rescheduledFromLessonId`;
- серия не ломается.

Статусы:
planned / completed / rescheduled / cancelled_student / cancelled_teacher

Оплата на конкретном уроке:
paid / unpaid

Суммы в v1 не считать.

## 8. Часовые пояса

При возможности хранить IANA timezone.
Пока зона неизвестна — временно `moscowOffsetMinutes`.

В календаре:
**Моё время | Москва | Время ученика**

## 9. Итоги урока

Контекст уже известен: ученик, дата, прошлое ДЗ.

Teacher вводит:
- тему;
- результат прошлого ДЗ;
- ошибки/фокус;
- комментарий (необязательно);
- новое ДЗ;
- дедлайн.

`Завершить урок`:
- завершает lesson;
- фиксирует прошлое ДЗ;
- создаёт новое ДЗ;
- обновляет кабинет;
- при необходимости создаёт доверенные gamification events.

Цель — до 60 секунд.

## 10. Домашки

Типы:
practice / written / interactive / other

Разделять:
- факт выполнения;
- качество.

У submission отдельно:
- `studentInput`;
- `teacherEvaluation`.

Файлы не обязательны в первой сборке на Spark.
До Storage использовать ссылки/результаты/текст.

## 11. Пробники

Глобальный список: ученик / дата / балл / оценка / динамика.

Форма поддерживает:
- task results;
- изложение;
- сочинение;
- грамотность;
- критерии;
- комментарии.

После сохранения:
- итог;
- оценка;
- динамика;
- task analytics;
- автоматический отчёт;
- «На что обратить внимание».

## 12. Отчёт по пробнику

Блоки:
- Результат;
- Части работы;
- Критерии;
- Сильные стороны;
- На что обратить внимание.

## 13. Аналитика

Каждый exam task получает `mastery 0–100`.

Mastery не равен одной попытке.

Источники:
- mockExams;
- practice homework;
- позже integrations/question bank.

Свежие данные важнее старых.
Одна попытка 1/1 не означает 100% mastery.

Статусы:
green / yellow / red / gray.

Показывать отдельно:
- готовность к экзамену;
- освоение изученного;
- последний пробник;
- текущую оценку;
- цель.

Формула живёт в отдельном analytics service.

## 14. Геймификация v1

XP:
- ДЗ выполнено +40
- до дедлайна +10
- 80%+ +10
- 100% +15 дополнительно
- mastery +10 п.п. → +20
- пробник +80
- личный рекорд +30
- первое 80% mastery по task +50
- первое 90% mastery +30
- streak 3/7/15 → +30/+70/+150

Все числа конфигурируемые.
500 XP = уровень v1.

Student не пишет XP.
В v1 награды создаются доверенным teacher action.

Ачивки:
Первый шаг, Боевое крещение, Точно в срок, Взял темп, Железная серия, Не остановить, Снайпер, Вот это рост, Камбэк, Личный рекорд, Первое освоение, Полпути, Почти готов, Готов к экзамену + динамические «Мастер №N».

## 15. Материалы

## 17. Адаптивность

Адаптивность является обязательной частью архитектуры с первой реализации, а не
отдельным этапом визуальной полировки.

- интерфейс ученика проектируется mobile-first;
- интерфейс преподавателя проектируется desktop-first;
- все ключевые функции доступны на телефонах, планшетах, ноутбуках и больших
  десктопных экранах;
- адаптивные сетки имеют отдельные промежуточные layouts для планшетов;
- горизонтальный скролл страницы не допускается;
- таблицы и аналитика на узких экранах перестраиваются в карточки или компактные
  представления без потери действий и данных;
- touch targets на мобильных имеют размер не менее 44×44 CSS px;
- нижняя навигация используется на мобильных там, где она улучшает доступ к
  основным разделам;
- формы, модальные окна, карточки, графики и календарь адаптируются к доступной
  ширине и не выходят за viewport;
- обязательные контрольные ширины: 360, 768, 1024 и 1440 px.

## 18. Не входит в v1

- Русский100 integration;
- voice input;
- CloudText-like checker;
- own question bank;
- parent auth;
- Telegram/email notifications;
- full EGE analytics;
- server-side auto rewards;
- mandatory Storage.
